筋トレアプリ API (0.1.0)

Download OpenAPI specification:

筋トレ記録とユーザー間の競争で継続を促すモバイルアプリのバックエンドAPI。

共通ルール

  • JSONの項目名はスネークケース。
  • 日時はすべてUTCのISO 8601形式（例: 2026-10-05T04:00:00Z）。
  • ユーザーIDはサーバーが発行するULID（26文字）。Firebase UIDは外部に出さない。
  • 認証はFirebase AuthのIDトークンを Authorization: Bearer <IDトークン> で送る。 「誰からのリクエストか」はトークンからサーバーが判断するため、 リクエストに自分のユーザーIDを含めることはない。
  • 定義されていない項目をリクエストに含めた場合は400を返す。

エラー

エラー時は全API共通で Error の形を返す。アプリは error.code で判定し、 error.message は開発者向けの説明として扱う。

users

ユーザー登録・プロフィール

初回登録（冪等）

Firebaseユーザーに対応するユーザーを作成する。

  • ユーザが未登録なら作成してstatus:201を返す。
  • 登録済みなら何も変更せず既存ユーザーをstatus:200で返す（上書きせず既存のものを）。
  • 同じリクエストを何度送っても結果は同じ。
  • handleはサーバーが user_ + ランダム英数字8文字で自動生成する （例: user_7k2m9xqa）。初回のusers/meへのリクエストでは、ユーザはhandleを指定することはできない。
  • timezoneはデフォで Asia/Tokyo になる。

プロフィール・公開設定の更新

送った項目だけを更新する部分更新（JSON Merge Patch / RFC 7396 の考え方に従う）。

  • 項目を送らない = 変更しない。
  • null を送る = 値を消す（bio のみ可能）。
  • privacy は中の項目単位で更新する（送らなかった中の項目はそのまま）。
  • 空のボディ {}、未定義の項目、変更不可の項目（id など）は400。

handleの変更ルール

  • 3〜20文字、英小文字・数字・_ のみ。
  • user_ で始まるもの、予約語（admin など）は不可 → 400（reason: HANDLE_RESERVED）。
  • 他人が使用中 → 409（HANDLE_TAKEN）。

退会

ログイン中のユーザーを退会させる。

  • 個人を特定できる情報（handle・display_name・bio・アイコン）を削除し、 他ユーザーの画面では「退会したユーザー」として表示される（匿名化・論理削除）。
  • handleは解放され、他のユーザーが使えるようになる。
  • サーバーがFirebase Authのアカウントも削除する。
  • 退会後はIDトークンが無効になるため、再送すると401になる。 退会リクエスト後の401は「退会完了」とみなしてよい。
  • 退会の確認ダイアログ等はアプリ側のUIで行う。

他ユーザーのプロフィール

指定したユーザーの公開プロフィールを返す。

  • 自分用の User とは別の、公開してよい項目だけの PublicUser を返す。
  • 存在しない・退会済み・IDの形式が不正な場合は、いずれも404（USER_NOT_FOUND）。
  • 自分のIDを指定した場合も PublicUser で返す（friendship_status は none）。

training_calendar

月間カレンダー表示用のトレーニング履歴

自分の1ヶ月分のトレーニング履歴を取得する

指定した月の、ログイン中ユーザーのトレーニング履歴を日付ごとにまとめて返す。

  • IDOR対策としてFirebaseが発行するトークンをAuthorizationヘッダーに含める リクエストにユーザーIDは含めない。
  • 「何月何日か」の判定は、DBに保存されたユーザーのタイムゾーン （デフォルト Asia/Tokyo）を基準に行う。
  • トレーニングをしていない日は days に含めない。
  • 指定月にトレーニングが1件もない場合は、days を空配列で返す（404にはしない）。
Authorizations:
firebaseAuth

month
required
string^\d{4}-(0[1-9]|1[0-2])$
Example: month=2026-10

取得する月。YYYY-MM 形式で、月は必ず2桁（ゼロ埋め）。
